## Pass 1 — Product scope, architecture and navigation

**Checks**
- One imported JSON object remains one independent Exercise card.
- Multiple topics remain attached to that one card.
- Original JSON remains separate from mutable display title.
- Exercise Library is reachable through phone/tablet navigation.
- Dashboard actions reflect feature availability.
- Practice, vocabulary, history and persistent Settings remain outside this implementation slice as documented.

**Finding and correction**
- The dashboard showed “Nhập bộ đề” as disabled / “Sắp ra mắt” although the Exercise Library import flow was already implemented.
- Connected that action to AppShell's Exercise Library destination and added a widget regression test.

**Result:** Product/navigation inconsistency corrected in source; widget verification pending on the target SDK.

## Pass 2 — Validation, persistence, async lifecycle and error handling

**Checks**
- JSON root/schema/required fields, topics, question IDs, answer presence, MCQ options, content hashing and size limits.
- UTF-8 size handling and memory allocation behavior for large pasted strings.
- SQL query parameterization, wildcard semantics and Vietnamese case-insensitive matching.
- SQLite/file-store transaction boundaries, orphan cleanup and startup failure paths.
- Clipboard/file picker exception handling and widget lifecycle guards.

**Findings and corrections**
- The validator encoded the entire pasted string before checking the 2 MiB limit. Added a cheap code-unit precheck before the byte-accurate UTF-8 check, with a multibyte regression test.
- Search treated `%` and `_` as SQL `LIKE` wildcards rather than literal user input. Escaped `!`, `%` and `_` and added a repository regression test. The SQL escape expression was separately exercised with Python's SQLite engine.
- Default repository initialization could leave an already-open SQLite database unclosed if file-store creation or orphan cleanup failed. Added best-effort database close while preserving the original initialization exception.
- Clipboard platform failures could escape the dialog. They now render an actionable error state.

**Result:** Corrections added and statically reviewed. Flutter unit/repository tests remain pending.

## Pass 3 — Regression tests, UI quality and project packaging

**Checks**
- Revisited the previous import-dialog failure and every text-entry/action interaction in `widget_test.dart`.
- Checked stable finders, keyboard visibility, enabled states, single-tap semantics and exception checkpoints.
- Checked responsive navigation, dashboard, theme, empty/loading/error states and current feature boundaries.
- Checked project ZIP for generated files, local paths, stale patch instructions and IDE-only files.

**Findings and corrections**
- The import flow now uses stable keys and hides the simulated keyboard before tapping “Kiểm tra”.
- The rename dialog had the same class of risk: its test entered text and tapped “Lưu” while the simulated keyboard could still be visible. Added stable keys and keyboard dismissal for rename too.
- Added exception assertions after important widget transitions and a dashboard navigation regression test.
- Replaced the patch-specific root README with a project README.
- Removed generated/local-only files from the deliverable, including `android/local.properties`, generated iOS Flutter config, iOS ephemeral files, `.flutter-plugins-dependencies`, and IDE metadata. Added generated iOS config paths to `.gitignore`.
- Updated the Android application label to `SelfLearn`.

**Result:** Regression guards and packaging cleanup added. The original dialog issue is not marked `Fixed` until the local Flutter test suite passes.
